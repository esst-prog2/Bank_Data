# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users
Financial analysts, finance students, and academic researchers who need European
bank figures (capital, RWA, NPL ratio, ROE, cost-to-income, balance-sheet items)
that they can trace back to the published filing they came from. Typical job:
compare a handful of banks on a set of financial and regulatory concepts, then
check or reuse the numbers. Secondary audience, confirmed but not designed for
first: the Advanced Programming course reviewers who grade the project.

## Product Purpose
`bank-data` is a Python package plus a static comparison dashboard. It retrieves
financial-statement and regulatory data for European banks from machine-readable
sources (ESEF filings, EBA Stress Test / Pillar 3 templates), maps source items to
standardized concepts, and returns a pandas DataFrame in which every figure carries
its source reporting item and provenance. Success: a user gets a figure they can
compare across banks and verify against the publication it came from.

## Positioning
The dashboard leads. You click bank logos on a map of Europe to build a basket of up
to 6 banks, pick concepts, and get a results table. It needs no backend: every number
is precomputed by calling the real package functions exactly as shipped
(`get_financial_data()`, `compute_rwa_density()`, `compute_cost_to_income_ratio()`,
`compute_npl_ratio()`), with nothing reimplemented for presentation.
Provenance is the supporting claim. Each figure is tagged by source template and
provenance (reported actual vs. scenario-projected). When two sources disagree, both
figures are shown with the gap explained on hover and are never silently reconciled.
Example: Erste Group's EU KM1 vs. EU OV1 RWA totals, about 1.5% apart.

## Operating Context
- Live dashboard: https://esst-prog2.github.io/Bank_Data/dashboard.html (source `docs/dashboard.html`, generated by `dashboard/build_dashboard.py` from `dashboard/comparison_data.json`).
- Direct function-call snapshots: `review.html` (Erste Group, single bank) and `compare.html` (Erste + BNP Paribas) under the same GitHub Pages site.
- Install path: Python package `bank-data` 0.1.0, Python >= 3.10, from the public GitHub repo esst-prog2/Bank_Data.
- Dashboard features: map-based basket (max 6 banks), concept picker that includes ratios standardized as a % of total assets or of total RWA, best value per ratio row highlighted, missing data shown as a dash with its real reason on hover, timestamped CSV export.

## Capabilities and Constraints
- Status: a course-term MVP. Pilot set of 28 EU banks, limited to issuers covered by ESEF. Not a hosted service or public API. No cross-framework reconciliation into a single value.
- Distinguishes data that is missing from the source from data the package failed to retrieve or process.
- Hosting: GitHub Pages from `docs/`. Pages there are static, self-contained HTML. The repo must stay public.
- Pages must not contain the author's personal information (name, email, etc.).

## Brand Commitments
- Name in use: "European Bank Financial Data Reconciliation" (README title); package name `bank-data`; repo `Bank_Data`.
- Voice from the README: plain, precise, and candid about limits. It states boundaries ("Not this term") and admits where earlier scope turned out wrong.

## Evidence on Hand
- Real: the live dashboard, the two snapshot pages, the 28-bank pilot list (`dashboard/pilot_28_leis.json`), bank logos (`dashboard/bank_logos/`), country flags, the Europe map SVG, and the Erste KM1/OV1 disagreement as a concrete worked example.
- Absent, and must not be fabricated: users, testimonials, adoption numbers, benchmarks, pricing, licensing terms beyond what the repo states.

## Product Principles
1. Every number is traceable to the publication it came from.
2. Show disagreement; don't hide it behind a single reconciled figure.
3. The demo runs the real code, with nothing simplified for presentation.
4. Be explicit about scope: what is covered this term and what isn't.
